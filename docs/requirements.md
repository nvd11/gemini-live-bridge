## 1. 项目背景与目标

### 1.1 背景
传统的智能语音助理系统通常基于串联的“流水线架构”（ASR 语音转文字 → LLM 文本推理 → TTS 语音合成）。此架构存在固有缺陷：
1. **端到端延迟高**：每个环节均产生缓冲延迟，整体对话时延往往在 2~4 秒以上，无法形成流畅对话；
2. **丢失情感与语调**：文本中间层抹除了用户语音中的语气、情绪、重音与迟疑；
3. **无法随时打断（Barge-in）**：在 TTS 播报过程中，用户无法自然插话，体验呆板。

Google 推出的 **Gemini 3.8 Live** 原生支持全双工语音流输入与直接语音流输出，带来了革命性的实时人机自然对话能力。然而，主流企业协作平台（飞书/Lark、Slack）并未开放 Bot 直接接入普通音视频电话通道的 WebRTC 音频流注入接口。

### 1.2 建设目标
构建 **Gemini Live Bridge** 微服务，通过“IM 快捷交互卡片 + 专属 H5 实时对讲网页 + 后端双向流式中转服务”，为飞书与 Slack 用户提供媲美微信电话、零门槛安装的极速全双工语音通话能力。

## 2. 用户角色与典型场景

### 2.1 用户角色
- **企业员工 / 主人**：日常使用飞书或 Slack 办公，希望在碎片化时间、通勤路上或专注思考时，直接通过语音与专属智能助理（如 Hebe）进行头脑风暴或任务布置。
- **系统管理员**：负责配置平台 Webhook、Gemini API Key 及并发配额管控。

### 2.2 典型用户旅程 (User Journey)
1. **指令唤起**：用户在飞书或 Slack 任意单聊或群聊窗口输入 `/call`（或点击菜单中的【📞 发起语音通话】）。
2. **接收卡片**：机器人秒级回推一张专属电话卡片，显示：“Hebe 已就绪，点击立即连线”。
3. **安全进入**：用户点击按钮，在移动端飞书内置浏览器或电脑端浏览器打开全屏极简科技感呼叫界面。
4. **即刻对讲**：页面自动请求麦克风，建立 WSS 连接后播报开场问候；用户随心开讲，AI 同步用自然语音回答，屏幕伴随波形跳动并实时输出双向转写文字。
5. **随时插话**：当 AI 正在回答时，用户直接开口打断，AI 瞬间闭嘴倾听，无缝切入新话题。
6. **挂断离场**：用户点击挂断按钮或关闭网页，连接自动释放，卡片状态更新或发送通话摘要。

## 3. 功能需求规格

### 3.1 平台交互与卡片触发模块 (IM Integration)
- **FR-101 (Slash Command 监听)**：
  - 支持监听飞书自定义机器人/应用指令 `/call` 及 Slack Slash Command `/call`。
  - 支持可选入参，例如 `/call hebe`、`/call thinking`（指定使用深度思考链模型）。
- **FR-102 (富文本交互卡片下发)**：
  - 飞书：利用飞书开放平台 Interactive Card（消息卡片 v2）渲染包含状态徽章、说明文案及【进入通话】行动按钮的卡片。
  - Slack：利用 Block Kit 渲染富文本卡片与 Button Action。
- **FR-103 (一键呼起链接生成)**：
  - 卡片按钮绑定服务公网 URL 并附带一次性短期加密凭证：`https://voice.domain.com/call?token=xyz...`。

### 3.2 会话鉴权与生命周期管理模块 (Session & Auth)
- **FR-201 (Ephemeral Token 签发)**：
  - 生成 256 位加密随机或带签名的 JWT 临时令牌（`session_token`）。
  - 令牌默认有效期为 5 分钟（自签发至初次握手）。
  - 包含元数据：`user_id`、`platform`（feishu/slack）、`channel_id`、`model_variant`（3.8-live 或 live-extended-thinking）。
- **FR-202 (单次使用与防重放)**：
  - 令牌仅允许一次成功的 WebSocket 连接建立；一旦握手完成，即刻核销，禁止二次复用。
- **FR-203 (通话最长限时与空闲挂断)**：
  - **最大通话时间保护**：单次通话上限默认 30 分钟（可配置），达到时间平缓挂断，防止意外消耗配额。
  - **静音超时挂断**：若建立连接后连续 2 分钟无任何上下行音频与文本活动，自动断开连接并回收资源。

### 3.3 H5 实时语音交互前端模块 (H5 Audio Client)
- **FR-301 (跨平台浏览器兼容)**：
  - 兼容 iOS Safari、Android Chrome、macOS/Windows 主流现代浏览器，特别是**飞书移动端内置浏览器 (Webview)**。
- **FR-302 (音频采集与重采样)**：
  - 使用 `navigator.mediaDevices.getUserMedia` 请求麦克风，开启硬件级 `echoCancellation`（回声消除）、`noiseSuppression`（降噪）和 `autoGainControl`（自动增益）。
  - 利用现代 **AudioWorklet** 节点将采集到的采样率自动重采样为 **16,000 Hz, 16-bit Signed Linear PCM (Little-Endian), 单声道**。
  - 将 PCM 音频切分为 100ms~200ms 的二进制块，平滑推送至 WebSocket。
- **FR-303 (音频无缝流式播放)**：
  - 接收服务端下发的 **24,000 Hz, 16-bit PCM (Little-Endian)** 音频分片。
  - 利用 Web Audio API 建立音频帧排队与抖动缓冲机制，确保音频连贯无爆音、无卡顿。
- **FR-304 (即时打断与静音截断 Barge-in)**：
  - 当本地 VAD（Voice Activity Detector）检测到用户再次开始发声，前端立即停止当前音频播放器中的所有待播队列，并向服务端发送打断控制帧（`interrupt`）。
- **FR-305 (交互界面与动效)**：
  - 动效：双向音频波形可视化（Listening 倾听态、Thinking 思考态、Speaking 说话态）。
  - 字幕：实时流式双向文本滚动呈现（用户说的话及 AI 回复文本）。
  - 控制：静音麦克风按钮（Mute）、一键挂断按钮（Hangup）。

### 3.4 双向长连接流式代理模块 (WebSocket Relay Gateway)
- **FR-401 (客户端 WebSocket 连接治理)**：
  - 提供安全的 `/ws/live/{token}` 接入点，进行严格的 Token 合法性与状态校验。
- **FR-402 (上游 Gemini Live API 长连接通道)**：
  - 使用 Google 官方 `google-genai` SDK 或标准 WSS 协议与 `wss://generativelanguage.googleapis.com` 建立全双工会话。
  - 握手首帧下发预设 System Instruction（人设与角色定位）、Voice 配置（如 `Puck` 或指定声线）以及响应模态（`AUDIO` + `TEXT`）。
- **FR-403 (全双工双向中继)**：
  - **上行中继**：接收前端 PCM 音频帧及文本帧，封装为 Gemini Live API 标准输入块送入模型。
  - **下行中继**：接收 Gemini 吐出的 24kHz 音频字节块与实时字幕文本，即时转发给客户端。
- **FR-404 (打断逻辑透传)**：
  - 当客户端发出打断请求时，通知上游模型取消当前轮次输出，并清理未下发缓冲。

## 4. 非功能性需求 (NFR)

### 4.1 性能与延迟
- **端到端感知时延 (E2E Latency)**：
  - 从用户话音结束（VAD 裁决）到听到模型首个音频分片播放，端到端延迟应控制在 **800ms 以内**（国内通过中继节点连接海外 Google API 最优时延控制在 600~1000ms 范围）。
- **音频流缓冲时间**：
  - 客户端音频发送切片粒度为 100ms，服务端转发处理开销小于 10ms。

### 4.2 平台安全性与隐私
- **传输层加密**：全链路必须强制 **HTTPS (TLS 1.3/1.2)** 与 **WSS**，严禁使用非加密 HTTP。
- **密钥零泄露**：Google API Key、飞书 App Secret 及 Slack Bot Token 仅在服务端持久化读取，严禁出现在任何前端静态资源或客户端下发报文中。
- **音频数据合规**：端到端音频流纯内存管道化处理，默认不落地存储录音文件，保护用户个人与商务隐私。

### 4.3 稳定性与可观测性
- **优雅重连与降级**：网络偶发丢包时支持心跳保活（Ping/Pong 15s），异常断开时向前端返回明确错误原因（如 Token 过期、连接超时、上游配额受限等）。
- **指标监控**：输出 Prometheus 兼容指标，涵盖当前活跃通话数、通话累计时长、上游 API 响应时延分布与异常错误计数。

## 5. 边界与演进规划

### 5.1 本期边界 (MVP Scope)
- 仅提供点对点单人语音对讲，不涉及多人会议室混音。
- 采用 H5 网页呼起模式，不依赖飞书或 Slack 的私有专有音视频协议。
- 默认采用标准对话模态，暂不开启本地文件大批量预加载（后续扩展）。

### 5.2 后续扩展 (Future Phases)
- **Function Calling 工具连通**：集成外部日程查询、邮件代发、智能家居控制等。
- **通话纪要沉淀**：挂断后自动调用文本模型整理要点，回推飞书/Slack 聊天框。
